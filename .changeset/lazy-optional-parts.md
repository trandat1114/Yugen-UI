Parts that only one option needs now load on demand (#350). `Nav` no longer imports Tooltip: the AppShell `Sidebar` passes the icon-rail tooltip to it, so a Nav outside AppShell goes from 29.9 to 12.0 kB gzip (Rolldown, as in Vite 8). Breadcrumb loads the menu of its "…" button only when `maxDisplayedItems` collapses items (initial chunk 40.2 → 13.5 kB), and StreamingMarkdown loads the citation card only when the text has citations (49.3 → 27.3 kB). Until the part arrives, which starts right after the first client render, the button or chip renders with the same size, classes and ARIA; a click or key press in that window opens the menu or card once it arrives, and focus moves to the real button. Server rendering and hydration always render that placeholder, so both sides produce the same HTML. A lean dashboard (YugenProvider, Nav, Breadcrumb, Card, Button, Badge, Field, Input) goes from 51.2 to 32.2 kB and an AI chat page (YugenProvider, StreamingMarkdown, PromptInput, MessageScroller, Reasoning) from 63.8 to 54.1 kB; apps that already use Menu, Tooltip or Popover elsewhere see little change. Tests that open the Breadcrumb menu or a citation card right after rendering need to wait for it (`findByRole`). With esbuild code splitting (`splitting: true`), an import from the package root puts these parts into the first chunk even when the app does not use them, because esbuild assigns whole files to chunks; import from subpaths such as `yugen-ui/Breadcrumb` there.
