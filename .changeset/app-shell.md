New `AppShell` (#161): the frame of an app, with `AppShellHeader`, `AppShellMain`, `AppShellAside`, `AppShellFooter` and a `Sidebar` (`SidebarHeader`, `SidebarContent`, `SidebarFooter`, `SidebarGroup`, `SidebarTrigger`, `SidebarRail`). From `breakpoint` up (a container query on the shell, named `app-shell`) the sidebar sits in the layout and collapses to an icon rail (`collapsible="icon"`, Nav labels move to Tooltips) or hides (`"offcanvas"`); below it the same content opens in a Drawer that closes when a link is followed or a Nav item is chosen. `layout="header"` puts the top bar across the full width with the sidebar below it; `scroll="page"` lets the whole page scroll with a sticky top bar and sidebar, for content sites (the top bar height is `--app-shell-header`). `Sidebar resizable` turns `SidebarRail` into a keyboard-operable splitter. Ctrl+B / ⌘B toggles the sidebar (`shortcut`), except in text fields, contenteditable and during IME composition; with several AppShells on a page only the one that has focus or was clicked last responds, and `SidebarTrigger` shows the label and the shortcut in its Tooltip. `persistKey` keeps the collapsed state and width in a cookie (read it on the server with `readAppShellCookie`); the Drawer is never saved. When the frame crosses the breakpoint with the Drawer open, it closes and focus returns to the trigger, or to the main region if the trigger is hidden. Skip link to the main region, `useAppShell()` for custom parts, strings in `messages.appShell`. `NavItem` gains `tooltip`. The SaaS, Dashboard, AI chat, Admin, Docs, Store, Blog, Landing and Starter templates use it.
