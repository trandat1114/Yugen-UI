# Design.md — Yugen UI 幽玄

*Tiếng Việt: [Design.vi.md](./Design.vi.md).*

**Yugen UI** is a design system for **React + Tailwind CSS v4**, created by **trandat1114**, inspired by
[Microsoft Fluent 2](https://fluent2.microsoft.design/) (token structure, scales, component behavior) and the component
catalog of [shadcn/ui](https://ui.shadcn.com/docs/components). The primary color is **Sakura 桜** (cherry blossom).

> Yugen UI is not an official Microsoft product. Token names and the spacing/typography/radius/elevation/motion scales
> follow Fluent UI React v9; the Sakura palette, gradients and brand ramp are defined by Yugen UI.

This document is a **set of mandatory rules**. Everyone (and every AI) adding or changing UI must follow each section exactly.

---

## 0. TL;DR — 14 rules that must not be broken

1. **Do not hard-code** HEX/rgb colors, px, ms or cubic-bezier in `.tsx`. Use only utilities mapped from tokens.
2. Tailwind's default palette **is disabled** (`bg-blue-500`, `rounded-lg`, `shadow-md`, `text-sm` do not exist).
3. Spacing uses Tailwind's numeric scale, within the ten steps of the Fluent ramp: `p-3`, `gap-2`, `px-5`, `mt-8`, `gap-1.5` (§3.2).
4. Font sizes use only the type ramp: `text-caption2 … text-display`. Weights are only `font-normal` / `font-semibold`.
5. Always merge classes with `cn()` (`src/lib/cn.ts`) — **do not** use plain `twMerge` (it wrongly removes `text-body1`).
6. Do not use the `dark:` variant. Theme (light/dark/high-contrast) and brand live in tokens (`data-theme`, `data-brand`).
   Use only logical properties (`ms/me/ps/pe/inset-s/inset-e`) so that RTL works; directional icons add `rtl:-scale-x-100`.
7. **Neutral** for surfaces/text/borders · **Brand (Sakura)** only for CTAs, selected/on, focus, links · **Semantic** only for status.
8. **Do not cover large areas with brand** (header, sidebar, page background, large cards).
9. **Gradients only for illustration/hero/marketing** — never on controls or to indicate state.
10. **Do not use color as the only signal**; text ≥ 4.5:1, UI components ≥ 3:1 (check on the Color › Accessibility page).
11. Complex behavior uses **Radix primitives** / `cmdk` / `react-day-picker`; icons are **Fluent System Icons** only: built into the library (`src/components/ui/_internal/icons.tsx`, generated by `npm run icons`), and `@fluentui/react-icons` in demos and blocks.
12. A new Component/Block is done only when it has a docs page (registry) or a file in `block-library` (see §8).
13. **Classes must be in Tailwind v4 canonical form** (`inset-s-L`, not `start-L`; `data-disabled:`, not
    `data-[disabled]:`; `h-110`, not `h-[440px]`). `npm run lint:classes` must report clean; fix automatically with
    `node scripts/canonical-classes.mjs --fix`.
14. **Every async operation has all 4 states** loading / empty / error / success, and follows Wait UX (§6.5):
    no loader flash under 300ms, a way out (Retry / Cancel) on error.

## 2. Token architecture

| Layer | Example | Who may use it |
|---|---|---|
| **Global** | `--grey-14`, `--brand-80`, `--red-shade-10`, `--shared-teal`, `--shell-light` | `tokens.css`; only `Decorative/*` and the docs color pages may read `--brand-*`, `--shared-*` |
| **Alias** | `--colorNeutralForeground1`, `--colorBrandBackground`, `--spacingM`, `--borderRadiusMedium`, `--shadow16`, `--durationNormal`, `--colorGradientSakura1` | `index.css` (mapped to Tailwind) |
| **Utility** | `text-foreground-1`, `bg-brand-background`, `p-M`, `rounded-medium`, `shadow-16`, `duration-normal`, `bg-gradient-sakura` | Component `.tsx` |

- Alias names **match Fluent UI v9 tokens 1-to-1** → they can be looked up in the Fluent documentation.
- **Theme**: light at `:root, [data-theme="light"]`, dark at `[data-theme="dark"]`.
- **Brand**: 16-step ramp `--brand-10 … --brand-160`, switched with `data-brand`:

  | `data-brand` | Brand80 (key) | Notes |
  |---|---|---|
  | *(default)* / `sakura` | `#C2347A` Sakura 桜 | 5.16:1 with white text; hue offset ~30° from the danger red so it is not mistaken for a delete button |
  | `web` | `#0F6CBD` Fluent Communication Blue | The original Fluent 2 brand |
  | `teams` | `#5B5FC7` | Indigo "Dusk" — used for the dusk BloomArt |

  Sakura ramp: `#240C16 · #391324 · #4C1930 · #61213F · #79274D · #912D5C · #A72F69 · #C2347A · #E24A92 · #FA65A8 ·
  #FB7CB2 · #FD8EBC · #FFA7C9 · #FEC1D7 · #FED6E4 · #FDEDF3` (steps 130–160 are petal tones).
  New ramps are generated by keeping the OKLCH lightness/chroma curve of Communication Blue and changing the hue; Brand80 must be ≥ 4.5:1 on white.
- **Nested theme/brand**: set `data-theme` and/or `data-brand` on any element. When nesting a brand inside
  a theme that differs from `<html>`, put **both attributes on the same element**. The element carrying the attribute should set its own `bg-*`.
- **App shell**: `bg-shell` (page background `#FFFBFC` / `#1C191B`) and `bg-shell-nav` (`#FFF7FA` / `#141213`) — neutrals with a very slight pink cast to match Sakura. Component surfaces still use the standard Fluent neutrals.

## 4. Color rules

> Color is a tool for expressing style, evoking emotion and conveying meaning. Like Fluent, Yugen UI has **three palettes**:
> neutral, shared, brand — with **Sakura** as the default brand.

### 4.1 Neutral — the foundation
- Black, white and grays for **surfaces, text, layout**; in components, neutrals usually indicate **state changes**.
- **Visual hierarchy**: the most important surface is the lightest — `bg-background-1` + `shadow-4`, getting darker toward the background
  (`background-2` → `background-4`). Build hierarchy with neutrals + elevation before reaching for color.

### 4.2 Shared & semantic
- Shared colors (avatars, calendars, badges, tags) are **used sparingly**, only to highlight important areas; in dark mode they shift lightness/saturation automatically through aliases.
- **Semantic** colors (danger / success / warning) are **only** for feedback, status and urgency; always paired with an icon + text; never decorative; never the only signal.

### 4.3 Brand — Sakura 桜
- ✅ Primary button / CTA, **selected/on** states (tab, checkbox, radio, switch, slider, toggle), **focus indicator**, links,
  the light tint `brand-background-2` for the selected item (nav, pagination).
- ❌ Do not cover large areas with brand; do not use brand for body text; do not mix two brands in one area.
- ❌ Do not use brand for destructive actions — use `appearance="danger"` (red `#C50F1F`, clearly different in hue from Sakura).
- Ramp steps for aliases (light / dark): Foreground1 80/100 · Foreground2 70/120 · Link 70/100 · Background 80/70 ·
  Hover 70/80 · Pressed 40/40 · Background2 160/20 · Background2Hover 150/30 · Background2Pressed 130/10 ·
  CompoundStroke 80/100 · Stroke2 140/50.

### 4.4 Interaction states
- Web: **darker as interaction increases** (rest → hover → pressed/selected); use the matching trio `X` / `XHover` / `XPressed`.
- **Focus**: the control color does not change; add a 2px `stroke-focus` outline only on `:focus-visible`.
- Disabled: `foreground-disabled` / `background-disabled` / `stroke-disabled`; do not use opacity.

### 4.5 Gradient — the expressive language
| Gradient | Light | Utility / component | Character |
|---|---|---|---|
| **Sakura** (signature) | `#C2347A → #E0659A → #A855C9` | `bg-gradient-sakura`, `text-gradient-sakura`, `<GradientText gradient="sakura">` | Cherry blossom pink → orchid |
| **Dusk** | `#6A5AE0 → #A855C9 → #E0457B` | `bg-gradient-dusk`, `text-gradient-dusk` | Indigo dusk → pink |
| **Sunset** | `#A855C9 → #E0457B → #D4704A` | `bg-gradient-sunset`, `text-gradient-sunset` | Dawn purple → pink → peach |
| **Aurora** | `#2886DE → #23A99B → #7D6CF0` | `bg-gradient-aurora`, `text-gradient-aurora` | Contrasting cool tones |
| **Brand** | `brand50 → brand80 → brand90` | `bg-gradient-brand`, `text-gradient-brand` | Follows `data-brand` |
| Hero glow | cherry blossom pink + lavender | `bg-hero-glow` | Background glow behind the hero |

Each gradient has a brighter dark variant. Every light stop reaches **≥ 3:1** on white.
`<WavyUnderline>` (wavy underline, stops automatically under `prefers-reduced-motion`) and `<BloomArt>` (brand-colored bloom) are used alongside them.

- ✅ Hero, illustrations, onboarding, empty states, marketing; at most **one** gradient accent per viewport; gradient text only at ≥ 28px.
- ❌ No gradients on Button, Input, Nav, Badge, Menu… or any other control; not to indicate state;
  not for body text/labels/figures; do not mix your own stops — add a token (with a dark value) if needed.

### 4.6 Accessibility
1. Text ≥ **4.5:1** (large text ≥ 3:1); UI components and control borders ≥ **3:1**. Decorative and disabled borders are exempt.
2. Let users choose the theme/brand when possible.
3. Do not use color as the only means of communication.
4. Check every new color pair on the **Color › Accessibility** page (computed directly from tokens, light & dark).

### 4.7 Glass — material for the navigation layer (Yugen Labs)
Enabled per component: `material="glass" | "glass-clear"` (Toolbar, TabsList, Nav, MenuPopover, PopoverSurface,
TooltipContent, DialogSurface, DrawerSurface, SheetContent), `appearance="glass" | "glass-prominent"` (Button),
`appearance="glass"` (Input / SearchBox). Utilities: `glass`, `glass-clear`, `glass-tinted`, `glass-scrim`,
`scroll-edge`, `scroll-edge-above`, `rounded-concentric`. Docs page: **Foundations › Glass**.

| Token | Light | Dark | Notes |
|---|---|---|---|
| `--colorGlassBackground` | white 80% | grey 16 82% | fg1 / fg2 ≥ 4.5:1 over pure white or pure black |
| `--colorGlassBrandForeground` | brand60 | brand140 | brand inside glass |
| `--colorGlassClearBackground` | black 40% | black 40% | always with `--colorGlassScrim` (black 35%) over images |
| `--colorGlassTinted` | brand70 90% | brand70 90% | white text ≥ 4.5:1 in every state |
| `--glassBlur` / `--glassSaturation` | 24px / 180% | | `--glassFilter: none` in high contrast |

- Inside `glass`, foreground-3/-4 use the foreground-2 color, brand uses a darker shade, and hover / pressed become transparent
  overlays. `src/test/glass.test.tsx` computes contrast from `tokens.css` for all 3 brands — changes to glass tokens must keep the test green.
- Solid background, no blur: `prefers-reduced-transparency`, `prefers-contrast: more` (adds a border), the high-contrast theme,
  `forced-colors`, browsers without `backdrop-filter`. Glass nested inside glass turns off blur automatically.
- ✅ Toolbars, tab bars, sidebars, menus, transient surfaces floating over content; one `glass-prominent` action per screen.
- ❌ No glass for content (Card, List rows, DataGrid cells); do not stack glass; no `glass-clear` over light images without a scrim.

## 5. Component authoring rules

1. **Consistent API**: `appearance`, `size` (`small | medium | large`), `shape`, `color` (semantic) or `intent` (level).
2. **Control height**: small 24px (`h-6`), medium 32px (`h-8`, default), large 40px (`h-10`).
3. **All states**: rest → `hover:` → `active:` → `disabled:` → `focus-visible` (§4.4).
4. **forwardRef** for components that wrap DOM elements; support `asChild` (Radix `Slot`) for action elements.
5. The user's `className` always goes **last** in `cn(...)`.
6. **Accessibility**: labels linked with `useId`; icon-only elements have `aria-label`; `aria-invalid`; `role="alert"` for errors;
   full keyboard navigation (Tree, Toolbar, List, Tabs, Menu, Combobox).
7. **Reuse shared classes, do not copy them**:
   - Fluent-style input → `fieldControlClass` / `fieldAppearanceClass` (`Field`, `Select`).
   - Label/hint/validation → wrap the control in `<Field>` (pass an element or a render prop `(props) => …`).
   - Floating surface → `popoverSurfaceClass` (`Popover`); menu item → `menuItemClass`, `menuPopoverClass` (`Menu`);
     listbox option → `listboxOptionClass`, `cmdkOptionClass`.
8. Signature details to keep:
   - Input/Textarea/Select/Dropdown/Combobox/DatePicker: `stroke-accessible` bottom border + a 2px brand bar that grows from the center on focus.
   - Tabs: active tab has semibold `foreground-1` text + a 3px brand bar; hover shows a gray bar.
   - Card: separated from the background with `shadow-4`. Menu/Popover/Toast: `shadow-16`. Dialog/Drawer: `shadow-64`.
   - Nav (component): hover `bg-subtle-hover`; selected `bg-brand-background-2-hover` + `text-brand-foreground-2` + a 4px brand bar.
     (The docs site sidebar uses a brand tint on hover — that is the docs site's own style.)
   - Badge defaults to circular/filled/brand; Radio has a 10px brand dot; the Slider thumb has an inner `background-1` ring.
   - SplitButton: the primary action is not repeated in the menu.
9. Do not add other UI/animation libraries (MUI, Ant, Framer Motion…).
10. **Custom floating surfaces** (rendered through a Portal) must spread `{...usePortalThemeProps()}` on the Content so they follow the theme/brand/dir of a nested YugenProvider.
11. **Fixed z-index scale**: `z-30` sticky top bar · `z-40` mobile sidebar overlay · `z-50` all overlays (Dialog, Drawer, Popover, Menu, Tooltip, listbox) · `z-100` Toast region. Do not use arbitrary z-index values.
12. **Focus**: never use `outline-none` without a replacement indicator; inside `overflow-hidden` areas use `-outline-offset-2` so the outline is not clipped.
13. **Announcements**: important errors in a Toast use `timeout: -1` (no auto-dismiss); async results without visible UI use `useAnnounce()`.
14. **Next.js App Router**: add `"use client"` at the top of each component file when copying it over; shared class constants (`fieldControlClass`…) can still be imported in client components.
15. **No API breaks in minor/patch releases** (from 1.0; before 1.0 they must be listed under "Breaking"). To remove a prop/value/export: add a replacement,
    mark it with JSDoc `@deprecated` and call `warnDeprecated(id, "use …", "x.0.0")` from `@/lib/deprecate` — remove it only in a later major release.
    Details: `#/concepts/versioning`.
16. **SSR safety**: do not read `Date.now()`, `Math.random()`, `window`, `matchMedia`, `localStorage` or layout sizes during render —
    do it in an effect, or with `useSyncExternalStore` and a `getServerSnapshot` (`useMediaQuery`). Ids use `React.useId()`.

## 6. Theming, text direction & globals

### 6.1 YugenProvider (equivalent to FluentProvider)
```tsx
<YugenProvider applyToDocument withToaster theme="light" brand="sakura" dir="ltr">
  <App />
</YugenProvider>
```
- `theme`: `"light" | "dark" | "high-contrast"` · `brand`: `"sakura" | "web" | "teams" | <custom brand name>` · `dir`: `"ltr" | "rtl"`.
- `applyToDocument` (root provider): writes `data-theme`, `data-brand`, `dir` on `<html>` so that portals (Dialog, Menu, Tooltip…) also get the right theme.
  A nested provider (without `applyToDocument`) wraps its content in `<div data-theme data-brand dir>`.
- Includes Radix's `DirectionProvider` (required for RTL) and `TooltipProvider`; `withToaster` mounts `<Toaster />`.
- `useYugen()` reads the current `{ theme, brand, dir }`.
- An inline script in `index.html` applies theme/brand/dir before React renders (no flash). The docs site accepts the query
  `?theme=dark&brand=web&dir=rtl` (like Storybook's `globals`) so links can be shared with the right appearance.

### 6.2 High contrast (`data-theme="high-contrast"`)
Black background, white text, **cyan `#1AEBFF`** accent (black text on the accent color), **yellow `#FFFF00`** links, **green `#3FF23F`** for disabled.
Every `shadow-*` becomes a 1px white border; gradients resolve to white. Components **need no changes** if they use only token utilities.
Do not rely on shadows or light background colors to convey state — always provide a border/text/icon.

### 6.3 RTL text direction
- Enabled with `dir="rtl"` (YugenProvider or `<html dir>`). The docs top bar has an **LTR / RTL** switch.
- **Logical properties are required**: `ms-* me-* ps-* pe-* inset-s-* inset-e-* border-s border-e rounded-s-* rounded-e-* rounded-ss/se/es/ee-* text-start text-end`
  (`start-*`/`end-*` still work but are not canonical — rule 13).
  Forbidden: `ml/mr/pl/pr/left/right/border-l/border-r/rounded-l/rounded-r/text-left/text-right` (except symmetric centering with `left-1/2 -translate-x-1/2`).
- Directional icons (left/right chevrons and arrows, prev/next, send, reply) add `rtl:-scale-x-100`. Do not flip neutral icons.
- Horizontal motion: add an `rtl:` variant (e.g. Switch thumb `rtl:data-[state=checked]:-translate-x-5.5`); the
  `animate-slide-*-start/end` animations already reverse through the `--yugen-dir` variable (1 | -1).
- Custom keyboard handling: swap the roles of ArrowLeft/ArrowRight based on `useDirection()` from `@radix-ui/react-direction`.
- Code (`<pre>`, HEX codes, account numbers) is always `dir="ltr"`.

### 6.4 Other globals
- The Example frame in the docs switches between **Yugen / Web / Teams × Light / Dark** and **High contrast**.
- Custom brand: use the **Theme Designer** page (`#/theme-designer`) → copy the block `[data-brand="name"] { --brand-10…160 }` into `tokens.css`.
  The algorithm is in `src/lib/brandRamp.ts` (`generateBrandRamp`, `adjustKeyForContrast`, `contrastRatio`).
- The docs site has a **Ctrl/⌘ + K** command palette (pages, components, concepts, switching theme/brand/text direction).

### 6.5 Wait UX — the waiting experience
Choose the signal by **expected** duration, not by habit (details: `#/concepts/wait-ux`):

| Duration | Display | Use |
|---|---|---|
| < 100ms | Nothing | Control hover/pressed states |
| 100ms – 1s | No loader, or a light signal after a delay | `useSpinDelay(loading, { delay: 300, minDuration: 500 })` |
| 1 – 3s | Inline spinner, or a skeleton if the layout is known | `<Button loading loadingText>`, `AsyncContent`, `SkeletonText/Avatar/Card/List/Table` |
| 3 – 10s | Determinate progress + what is happening + allow cancel | `ProgressBar value`, `PageProgress`, `Trace` |
| > 10s | Run in the background, let the user leave, notify when done | `toast`, `useAnnounce` |

- **No flashing**: a loader appears only when the wait exceeds 300ms, and once shown it stays for ≥ 500ms (`useSpinDelay`).
- **Keep the layout still**: skeletons must match the size of the real content; a button in `loading` keeps its width.
- **Page transitions**: `<PageProgress />` once at the app root + `<PageProgressFallback>` as the `Suspense` fallback.
- **Optimistic**: only for operations that almost always succeed and can be undone (`useOptimisticList`); on error, revert and report it.
- **Errors**: `ErrorState` / `AsyncContent status="error"` always offer a **Retry** action; never indicate errors by color alone.
- **A11y**: loading regions have `aria-busy`; results without visible UI are read through a polite live region; do not move focus to the loader automatically.

### 6.6 Desktop & mobile adaptation
- Same content, two forms: **Sheet** is a side panel (`side="start" | "end"`, `size`) on wide screens and a **draggable bottom sheet**
  below `breakpoint` (default 768px) with `snapPoints` (default `[0.5, 0.9]`). Force one form with `mode="side" | "bottom"`.
- Areas that must not start a drag (sliders, horizontally scrolling lists) get `data-sheet-no-drag`. The footer sticks to the bottom and leaves room for the safe area.
- `Drawer` is still used for fixed panels on desktop (overlay/inline); primary navigation on mobile uses Sheet/Drawer `start`.
- Branch on screen size with `useMediaQuery(query, { defaultValue })` — `defaultValue` is the value during SSR.
- Media frames use `AspectRatio ratio={16 / 9}` so the layout does not shift while images/videos load.

### 6.7 Docs site voice & toolbars
- Short sentences, state the facts, give numbers when available. No marketing adjectives ("powerful", "seamless", "smooth"…),
  no asides set off with "—", no three-part lists only for rhythm, no instructions for the obvious ("hover to…").
- Internal rules (gradients only for illustration…) live in this file, not on the home page.
- "Based on Fluent 2" appears only in the footer and on the migration-from-Fluent page. Not in the hero, sidebar or meta description.
- Toolbars do not wrap: every button is `shrink-0 whitespace-nowrap`; when space runs out, show only the icon (the text becomes `sr-only`
  or an `aria-label`), never let the text break onto a new line. One button per function; do not place two buttons that do the same thing.
- Check at 360 · 390 · 768 · 1024 · 1280px; there must be no page-wide horizontal scroll.

Labs-specific rules:
- **Chart**: choose the chart form first, then the colors · categorical colors use `--colorChartCategorical1…8` **in a fixed order**, never rotated;
  series 9 onward are grouped into "Other" (`--colorChartOther`) · **one Y axis**, never two · a legend when there are ≥ 2 series ·
  text/numbers use text tokens, not series colors · always a tooltip (hover + keyboard) and an **equivalent data table** (`ChartTable`) ·
  dark mode has its own palette, checked on dark backgrounds · a new palette must pass the color-blindness checks before it is added to `charts.css`.
- **Trace**: status always has an icon + text (not color alone); the running step shows live elapsed time; status changes are read through a polite live region.
- **MessageScroller**: auto-scroll down only when the user is at the bottom; if they are reading older messages, show an "N new messages" button; loading more history keeps the scroll position;
  a streaming message is read to screen readers only once it has been fully received.
- **Questionnaire**: one question per screen; Enter to continue, number keys to choose; validate `required` before moving to the next question; a review step before submitting.
- **CodeBlock**: always `dir="ltr"`; the copy button has a "Copied" state that screen readers announce.

### 7.2 Known limitations
- **Resizable** in RTL: horizontal groups flip with the text direction (`mirrorInRtl`, on by default) — `react-resizable-panels` already orders panels in
  visual order, so dragging and arrow keys move in the pointer's direction (covered by an e2e test). `mirrorInRtl={false}` keeps the LTR layout.
- **Sheet** in bottom form: drag/swipe gestures have only been tested with a mouse and a touch emulator; they still need testing on real iOS/Android devices.
- **Chart** is hand-written SVG: no log axis or maps yet; the brush always runs left→right like the plot area (even in RTL); very large datasets should be sampled first.
- Not available yet: a full ColorPicker, a TimePicker that crosses midnight. Overflow needs items with a natural width (no `flex-1`).

## 8. Extension workflow

### Adding a component
1. Create `src/components/ui/<Name>/<Name>.tsx` following §5, and add `export * from "./<Name>/<Name>";` to the right group in `src/components/ui/index.ts`.
2. Add a `ComponentDoc` to a file in `src/docs/registry/` (or a new file that exports `docs`): `slug`, `name`,
   `category` (one of `CATEGORIES` in `src/docs/types.ts`), `lead`, `description`, `importCode`, `hero`,
   `examples` (**`code` must be identical to the JSX in `render`**), `dos`/`donts` (2–3 points), `props`.
3. The sidebar, search and home page are generated from the registry — do not edit them by hand.

### Adding a block
1. Create `src/docs/block-library/NN-name.tsx` with `export const meta = { title, description, order }` and `export default function …`.
2. Import only from `@/components/ui` + `@fluentui/react-icons` so that users can copy the whole file.
3. The "Code" tab shows the source of that file automatically (`?raw`).

### Adding a Concept page
1. Create `src/docs/concepts/<slug>.tsx` (default export: the page) and `src/docs/concepts/<slug>.meta.ts` with
   `export const meta: ConceptMeta = { slug, title, group, order, lead, toc }` (`group` is one of `CONCEPT_GROUPS`).
2. The sidebar entry, the Ctrl+K palette entry and the `#/concepts/<slug>` route are generated automatically; the page is lazy-loaded.

### Releasing a version (Changesets + News + npm)
0. In every PR with user-visible changes: `npx changeset` (patch / minor, a summary for users). Since 0.6.0
   `CHANGELOG.md` is generated by Changesets — do not edit it by hand.
1. `npm run version-packages` (= `changeset version` + sync of `templates/` + lockfile) — merges changesets into `CHANGELOG.md` and bumps `version` in `package.json` (per SemVer; while still
   on `0.x`, an API change = minor + `breaking`). The docs site's `SITE.version` reads directly from `package.json`; no edit needed.
2. Add `<version>.vi.md` and `<version>.en.md` to `src/docs/news/yugen-ui` (sections `## Mới` / `Cải tiến` / `Sửa lỗi` /
   `Thay đổi lớn` in the Vietnamese file, `## New` / `Improved` / `Fixed` / `Breaking` in the English file, each item with a `[→](/path)` link to a docs page;
   wiki › Release Process › News on the What's new page). The "What's new" dot on the top bar appears automatically for people who have not seen it yet.
3. `npm install --package-lock-only` → `npm run check:release` (`package.json` = `src/docs/news` = `CHANGELOG.md`) →
   `npm run typecheck && npm test && npm run build && npm run size` → `npm run pack:check` to preview the package contents.
4. Commit, then `git tag vX.Y.Z && git push --tags` — the `.github/workflows/release.yml` workflow checks the tag, runs the tests,
   builds and runs `npm publish --provenance` (npm trusted publishing, no token; a tag containing `-` → dist-tag `next`).

## 9. Pre-merge checklist

- [ ] No arbitrary HEX/px/ms in `.tsx` (except illustrations in `Decorative/`, the logo, and docs sample data).
- [ ] Spacing uses the numeric steps of the ramp (§3.2); font sizes use the type ramp; shared classes are reused (§5.7).
- [ ] Colors match their roles (§4); no brand on large areas; no gradients on controls.
- [ ] All hover / pressed / disabled / focus-visible states are present; the keyboard works.
- [ ] Checked in Yugen / Web / Teams × Light / Dark and against the contrast table.
- [ ] Has a registry entry (or a block file); the sample code matches the render.
- [ ] Async operations have loading / empty / error (with Retry) / success; loaders use `useSpinDelay` (§6.5).
- [ ] Checked in RTL and on a 390px screen (Sheet/Drawer, tables and charts do not overflow horizontally).
- [ ] New components are exported from `src/components/ui/index.ts` (so they are in the npm package).
- [ ] `npm run typecheck`, `npm run lint:classes`, `npm run build` all pass with no warnings.
- [ ] `npm test` and `npm run test:e2e` pass (axe reports no errors); intentional UI changes update the `test:visual` screenshots.
- [ ] `npm run size` stays within budget (`.size-limit.cjs`); raising a `limit` needs a reason in the PR.
- [ ] User-visible changes have a changeset (`npx changeset`).
- [ ] Content (docs, templates, CLI messages) follows [wiki › Writing](https://github.com/trandat1114/Yugen-UI/wiki/Writing).
